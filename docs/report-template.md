## 2. Змінений маршрут

Маршрут отримання підсумку за критичністю:
* **Браузер (UI):** Натискання кнопки `btn-summary` у `Client/index.html`[cite: 1].
* **Браузер (JS):** Обробник у `Client/app.js` виконує HTTP-запит `GET /api/incidents/severity-summary`[cite: 1].
* **API (Endpoint):** Маршрутизатор знаходить метод в `IncidentEndpoints.cs`[cite: 1].
* **API (Application Layer):** Викликається `IncidentQueries.GetSeveritySummaryAsync`[cite: 1].
* **БД (PostgreSQL):** Через `SecureLabDbContext.Incidents` / таблиця `incidents` виконується агрегація[cite: 1].
* **API (DTO):** Результат повертається як `IncidentSeveritySummaryResponse` у форматі JSON[cite: 1].
* **Браузер (Рендер):** Текст безпечно записується у DOM через `textContent`[cite: 1].

## 5. Security-сценарій

Для ЛР 1 профілі з дефектами (вразливим станом) не розподіляються[cite: 1]. Основна увага приділена перевірці безпечного базового маршруту, недовірених даних, використанню безпечних DOM-приймачів (`textContent`) замість небезпечних (таких як перетворення даних на HTML)[cite: 1], а також дотриманню безпечного Git-циклу без розголошення секретів у diff[cite: 1].

## 6. Висновок

Систему успішно розгорнуто, контейнер бази даних PostgreSQL підключено[cite: 1]. Успішно простежено маршрут від браузера до бази даних та реалізовано мале наскрізне розширення (`severity-summary`)[cite: 1]. Для розширення створено окремий DTO-контракт, щоб зменшити ризик розкриття даних[cite: 1]. Доведено, що клієнтська частина відображає дані безпечно, оскільки текст не інтерпретується як HTML[cite: 1]. Усі базові сценарії, а також порожній та некоректний HTTP-сценарії відпрацьовують правильно, відтворюваність системи через seed/reset підтверджено[cite: 1].
